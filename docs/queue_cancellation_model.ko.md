# 호가 잔량 감소의 확률적 취소 모형

작성일: 2026-10-27 KST

## 사용 흐름과 적용 범위

모의거래 → **체결 모형 설정 → 틱 외 잔량 감소 처리**에서 확률 취소를 선택한다. 기본 가중치 1, 분할 수 32, 시드 1이다. 계좌를 실행하면 주문별 앞·뒤 외부 잔량과 다음 취소의 앞쪽 확률, 최근 취소 추정 기록을 볼 수 있다. 같은 설정 복사에는 이 네 값도 포함된다. 취소 모형은 전략 신호가 아니라 체결 가정이므로 전략 등록값과 별개인 계좌 초기조건에 저장한다.

현재 실행 대상은 빗썸 현물 maker 재생이다. OKX 참조 호가는 빗썸 큐를 변경하지 않는다. 실제 주문 ID별 L3 자료가 없으므로 취소 위치는 **확률적 가정**이며 관측 사실이나 실제 체결 확률을 뜻하지 않는다.

## 1. 틱과 취소 구분

같은 방향·가격이 연속 두 호가에서 확인되고 수량이 유효할 때 다음 값을 계산한다.

```text
Qprev = 이전 호가의 외부 잔량
T     = 두 호가 사이에 관측한 해당 방향·가격의 소진량
Qnext = 새 호가의 외부 잔량
R     = max(0, Qprev − T)
C     = max(0, R − Qnext)  # 틱으로 설명되지 않는 순취소 추정량
A     = max(0, Qnext − R)  # 순추가 추정량
```

예를 들어 잔량이 100 → 70이고 중간 틱 소진량이 20이면 취소 추정은 10이다. 틱이 없으면 30을 취소로 추정한다. 틱으로 20이 소진됐는데 새 잔량이 여전히 100이면 20이 새로 추가됐다고 보고 큐 뒤에 넣는다. 취소와 신규 주문이 같은 구간에 함께 발생하면 순변화만 보이므로 각각의 총량을 복원하지는 않는다.

`T`는 정확히 해당 가격에서 관측한 공격 방향 틱 수량과 기존 가격 우선 매칭기가 해당 큐에서 소비한 수량 중 큰 값이다. 두 값은 겹치므로 더하지 않는다. 내 주문이 없던 동안의 해당 가격 틱도 추적하며, 이후 주문 도착 시 초기 앞 물량을 이미 소진된 만큼 줄인다. 해당 가격과 반대 방향 틱·OKX 틱은 섞지 않는다.

재생은 기존 `desktopTime` 순서와 같은 ms에서 틱 우선 규칙을 사용한다. 다음 호가는 그 사이 수신한 틱을 반영한 것으로 가정한다. 서버 시퀀스 없이 지연 수신된 틱·호가의 실제 인과 순서를 완벽히 복원할 수는 없다. 원본에 틱이 유실되면 취소를 과다 추정할 수 있으므로 보수 모형과 시드별 결과를 비교할 수 있게 한다.

## 2. 하나의 공유 FIFO

같은 방향·가격에는 다음과 같은 하나의 큐를 둔다.

```text
외부 30 → 내 주문 A → 외부 20 → 내 주문 B → 외부 50
```

외부 순추가량은 맨 뒤에 붙는다. 뒤에 넣은 물량을 다음 주문 도착 때 앞쪽에 중복 생성하지 않는다. 새 내 주문은 그 시점의 맨 뒤에 들어간다. 취소 대상은 외부 구간뿐이며 내 주문 A/B의 수량·예약 잔고·우선순위는 그대로 둔다. 여러 내 주문에 각각 독립 취소량을 적용하지 않는다.

취소량 C를 기본 32개 묶음으로 나눠 각 묶음마다 외부 구간을 추첨한다. 선택 구간 잔량보다 묶음이 크면 그 잔량까지만 취소하고 남은 양을 다시 추첨한다. 매번 줄어든 잔량으로 가중치를 다시 계산한다. 외부 구간이 하나뿐이면 추첨 없이 차감한다. 결과는 전체 C를 넘지 않고 음수 잔량을 만들지 않는다. 취소량이 큐의 추정 외부 잔량을 초과하면 외부 잔량까지만 반영한다.

같은 위치에 연속한 외부 구간은 합쳐 보관한다. 내 주문 N개가 있으면 외부 구간은 최대 N+1개라서 호가가 늘어날 때마다 큐가 무한히 커지지 않는다.

## 3. 확률과 조절값

내 주문이 하나이고 앞 외부 잔량 F, 뒤 외부 잔량 B, 앞쪽 가중치 b이면:

```text
P(앞쪽 취소) = b × F / (b × F + B)
P(뒤쪽 취소) = B / (b × F + B)
```

F=30, B=70이면 b=1일 때 앞쪽 30%, b=2일 때 약 46.15%, b=0.5일 때 약 17.65%다. 앞 또는 뒤가 0이면 나머지 쪽에서만 취소하고 양쪽 모두 0이면 확률을 `null`로 표시한다. 화면 확률은 **현재 상태의 다음 추첨 확률**이며 한 호가에서 취소될 총량의 확정 배분 비율이나 내 주문의 체결 확률이 아니다.

내 주문이 여러 개이면 외부 구간 i의 가중치는 `잔량 × [1 + (b−1) × (1−k/N)]`이다. N은 내 주문 수, k는 그 구간보다 앞에 있는 내 주문 수다. 모든 내 주문 앞에는 b, 모든 내 주문 뒤에는 1, 중간에는 선형 보간한 계수를 쓴다. 각 주문의 앞쪽 확률은 그 주문 앞 외부 구간 가중치 합을 전체 가중치 합으로 나눈 값이다. b=1이면 모든 구간에서 수량 비례다. 특정 내 주문별로 별도 가중치를 쓰는 기능은 없다.

| 실행 설정 | 기본값 | 범위·의미 |
|---|---|---|
| `queue_cancel_mode` | `probabilistic` | 확률 취소 또는 `conservative` 기존 보수 모형 |
| `queue_cancel_bias` | `"1"` | 0.01~100. 클수록 앞쪽 취소를 더 자주 선택 |
| `queue_cancel_chunks` | 32 | 1~256 정수. 작으면 큰 덩어리가 취소되어 변동이 커지고, 크면 여러 번 나눠 선택 |
| `queue_cancel_seed` | 1 | 0~4294967295 정수. 같은 입력·가상 시각 명령·시드로 재현 |

분할 수는 실제 주문 개수나 코인 주문 단위가 아니다. 집계 잔량에서 알 수 없는 취소 크기의 변동을 조절하는 모형 값이다. 외부 수량은 소수로 관리하고 내 주문의 최소 거래 단위로 억지 반올림하지 않는다.

## 4. 체결·누락 경계

- 취소만으로 내 주문을 체결하지 않는다. 앞 물량이 0이 되어도 이후 유효한 틱이 있어야 체결한다.
- 취소 대기 중인 내 주문도 외부 추정 취소로 없어지지 않는다. 실제 모의 취소 확인 전 틱 체결·예약 잔고 규칙을 유지한다.
- 내 모의체결이 실제 테이프의 외부 체결을 대신 차지할 수 있다. 다음 호가에서 남은 외부 잔량이 관측값보다 많으면 앞 외부 구간부터 체결 반영량으로 대사한다. 이를 취소 추첨으로 세거나 내 주문을 추가 체결시키지 않는다.
- 가격이 5호가 밖으로 사라지거나 수량이 누락되면 0으로 간주하지 않는다. 확률 모형에서는 큐를 미확인으로 전환하고 그 가격 체결 추정을 보류한다.
- 해당 가격이 다시 관측되면 새 외부 물량을 보수적으로 모든 기존 내 주문 앞에 배치한다. 기존 내 주문 사이의 FIFO는 유지한다. 관측 공백의 취소량은 만들지 않는다.
- 명시적으로 관측된 수량 0은 유효하다. 남은 외부 물량을 취소 추정으로 없앨 수 있지만 내 주문은 그대로다.

## 5. 재현·저장·화면

난수기는 실행마다 독립적으로 만들며 UI 조회·배속·저장 주기는 난수를 소비하지 않는다. 현재 모형 버전은 `weighted-segments-v1`이다. 같은 원본 순서·설정·가상 시각의 수동 명령이면 빠른 실행, 1×, 32×의 취소 배분·체결·손익이 동일하다. 다른 시드로 새 계좌를 만들면 추정 위치 불확실성을 비교할 수 있다. 서버 중단 후 난수 상태를 복구해 이어 실행하는 기능은 없으며 처음부터 같은 조건으로 재실행한다.

- `initial_config/config`: 모형 선택, 가중치, 분할 수, 시드를 고정한다.
- `queue_model`: 모형 버전, 누적 추첨 횟수, 취소 추정 이벤트 수·반영 외부 수량을 저장한다.
- `orders`: `queue_ahead`는 내 선행 주문 포함, `queue_external_ahead/behind`는 외부만, `queue_front_cancel_probability`는 다음 추첨의 앞쪽 확률이다.
- `queue_cancel_events`: 최근 100개 취소 추정에 이전/새 수량, 틱 소진량, 추정/반영 취소량, 주문별 취소 전·후 위치를 저장한다. 전체 취소 로그 무제한 보관은 아니다.
- 각 체결의 `queue_position/queue_model`: 해당 체결을 적용하기 직전 큐 위치와 모형 누적값을 고정한다. 이후 호가로 다시 쓰지 않는다. 전체 결과 JSON에 포함한다.

과거 실행 결과는 수정하지 않는다. 설정이 없는 저장 계좌를 복사하면 `conservative`를 명시해 이전 방식으로 재실험한다. 새 API 요청·새 계좌 입력은 확률 모형이 기본이다. 서버 업데이트 전에는 프런트엔드가 지원 여부를 확인하여 새 입력을 비활성화하고 이전 API에 새 필드를 보내지 않는다.

미확정 가정과 나중에 변경할 사항은 [Q-009](strategy_registration_queries.ko.md)에 기록했다. `tests/test_queue_cancellation.py`는 수량 보존·공유 FIFO·통계적 비율·시드 재현·틱 중복 차감 방지·앞뒤 추가·관측 공백·취소 경쟁·모드별 결과 동일성과 저장을 검증한다.
