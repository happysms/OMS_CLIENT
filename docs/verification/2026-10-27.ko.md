검증 대상 제품 버전은 `33e64d7`이다. 오늘 KST 기준 커밋 17개와 이 대화에서 요청한 기능을 대조했다. **Python 테스트 524개, DOM 화면 시나리오 24개, JavaScript 문법 검사, 그림 생성물 검사 모두 통과했다.** 제품 코드의 수정은 필요하지 않았고, 화면 테스트의 오래된 데이터·기대값을 갱신해 저장소로 옮겼다.

## 지정가 사례의 구현 상태

142개는 **사례 카탈로그 전체**다. 실행 구현 62개, 부분 지원 17개, 모형 가정 16개, 미지원 설계 47개로 분류되어 있다. 문서·그림 검사 통과를 미지원 사례의 실행 검증으로 계산하지 않았다. 상세 범위는 [지정가 실행 대조표](../limit_execution_coverage.ko.md)를 따른다. 일반 지정가를 포함한 OKX 선물 원장·Point 전체 헤지 실행도 후속 구현 범위다.

## 발견한 테스트 문제와 처리

처음 재실행한 임시 화면 스위트 23개 중 6개가 실패했다. 제품 오류가 아니라 과거 테스트가 뒤에 추가된 기능을 반영하지 못한 경우였다.

- 손익 표가 환율·거래대금 열을 포함하면서 paper 19열, replay 17열이 되었는데 이전 열 수를 기대했다. 현재 열과 거래대금 제목까지 검사하고 기존 가격·손익 숫자 검증은 유지했다.
- 과거 Point 표시 이름과 두 전략만 있던 카탈로그를 기대했다. 현재 registry에서 만든 세 전략과 안정적인 ID로 표시 이름을 찾아 검증한다.
- 과거 계좌 복사가 원본 전략 revision을 비동기로 읽는 GET을 가짜 API에서 지원하지 않았다. 해당 읽기를 제공하고 완료 후 복사값을 확인하며 매매 변경 요청이 없음을 계속 검사한다.

스크립트를 `tests/frontend/scenarios/`로 옮기고 절대 프로젝트 경로·공유 `/tmp` 카탈로그 의존성을 제거했다. 뒤이어 디스크·보관 정책 화면 시나리오 하나를 추가하여 최종 **24/24**를 확인했다. 통과한 영역 전체를 반복하지 않고 수정한 `pnl-currency`와 새 `storage`만 마지막에 다시 검증했다. JSON 보고서는 각 시나리오의 마지막 통과 결과와 소스 hash를 기록한다.

## 성능 확인

합성 시장 이벤트 20,000개와 임시 저장소로 6개 시나리오를 한 번씩 실행했다. 고정한 성능 기준치를 통과했다고 주장하는 벤치마크가 아니라 현재 경로가 동작하는지 확인하는 측정이다.

| 시나리오 | 이번 실행 소요 |
|---|---:|
| 주문 없는 재생 | 0.168초 |
| 주문 100개 재생 | 0.702초 |
| MM 재생 | 4.384초 |
| 상태 snapshot 조회 묶음 | 0.922초 |
| HTTP 상태 조회 묶음 | 0.012초 |
| 원본 스트림 변환 | 0.071초 |

숫자·시간 formatter의 이전/현재 출력 동등성도 통과했다. 별도 microbenchmark에서는 이번 측정의 중앙값 기준 약 27.5배 차이가 났지만 전체 화면이나 서버의 속도 향상률은 아니다. 과거 성능 기록 뒤 체결·손익 보고 필드가 추가되어 원본 스트림을 제외한 전체 결과 hash는 과거 기록과 다르므로, 이를 과거 결과 동등성 통과로 표시하지 않았다.

## 검증하지 않은 운영 경로

- 실제 거래소 개인 API와 실주문, 실제 거래소 네트워크 장애: 실행하지 않음.
- 원격 WSS 게이트웨이와 상대 실행 서버의 종단 간 연결: 아직 구현 전.
- Point·minmaxma의 전체 재생 실행, 실제 체결 업로드·비교·보정: 아직 구현 전.
- 실제 브라우저의 시각적 배치: DOM 기능 검증으로 대체할 수 없음.
- 실행 중인 서버의 재시작·배포: 수행하지 않음. 코드상 기본 차단과 새 기능은 해당 버전 서버 시작 후 적용됨.

운영 데이터와 가상계좌 결과는 수정하지 않았다. 자동 삭제 검증은 임시 디렉터리에서만 수행했다. 기존 pandas/NumPy 시간 단위 관련 DeprecationWarning은 남아 있으며 테스트 실패는 아니다.
