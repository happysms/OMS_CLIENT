# 전략 등록과 모의계좌 연결

`전략 관리` 탭에서 전략 유형을 선택하고 이름·설명·설정값을 등록한다. 현재 유형은 **일반 단일 거래소 메이커**, **Point(point2_st)**, **minmaxma(point_st)**다. 같은 유형으로 여러 설정을 이름 붙여 저장할 수 있다. 임의 Python/JavaScript를 올려 실행하는 기능은 아니다.

사용 흐름은 `전략 등록 → 모의계좌에 적용 → 종목·초기자산·기간 입력 → 새 계좌 생성/실행 → 계좌별 전략 버전·체결·손익 보관`이다. 전략은 자금을 갖지 않고, 계좌는 선택한 전략 설정을 실행 시점에 복사한다.

## 현재 등록 유형과 실행 범위

### 일반 단일 거래소 메이커

현재 실행 가능한 거래소는 빗썸 현물이다. OKX를 선택하면 기존 재생기와 같이 참조 호가·틱으로만 사용한다.

| 설정 | 기본값 | 적용 |
|---|---|---|
| `direction` | `both` | 양방향·매수만·매도만 중 선택. 금지 방향에 전략 신규 주문을 내지 않는다. 수동 주문은 별도다. |
| `max_quote_age_ms` | 1000 | 100~10000ms. 시세 유효성, 오래된 전략 주문 취소, 시작 평가, 주문 도착 검증, 시장 평가에 사용 |
| `theory_mode` | `midprice` | 전략이 `(best_bid + best_ask)/2`를 출력. `none`은 이론가 미제공 |

호가·지연 기준은 사용한 버전에 고정된다. 수량 단위·최소 주문 금액·수수료·전송 지연은 시장/체결 모형의 입력으로 계좌 실행 설정에 남긴다. 실제 주문은 기존 maker 전용 대기열 모형으로 처리한다.

중간가 이론가는 사용자 응답을 기다리지 않고 적용한 초기 가정이다. 계좌 평가 코드에 고정한 계산식이 아니라 전략의 출력 방식이다. 나중에 전략 구현을 추가하면 그 전략의 자체 이론가를 같은 입력 계약으로 전달한다.

### Point · point2_st

확인 기준은 `Tsystem2` 커밋 `d7dcd97a35fa32b56813d16b92ee53e1604d5c06`의 `sys_v2/strategy/point2_st.js`와 [재생 설계](../../docs/point2_replay_design.ko.md)다. 원본 운영 설정이나 개인 API를 실행하지 않는다.

등록한 Point는 다음 설정을 보관한다.

- `direction`: 양방향/매수/매도
- `baseline_bps=-100`, `buffer_bps=10`, `pricing_fee_bps=0`
- `max_spot_krw=20000000`, `reserve_krw=5000000`
- `max_hedge_qty=86000`(0은 한도 해제), `hedge_tolerance_krw=50000`
- `collateral_utilization=0.8`, `quote_interval_ms=500`
- `hedge_execution=post_only`: 원본 헤지 방식. 일반 지정가 GTC/IOC/시장가를 선택하면 명시적 변형으로 기록

프로필에는 `quote_mode=fx`, `reference_source=okx_swap`, `fx_source=bithumb:USDT`, MA 비활성, 현물 GTC, 원본 참조와 헤지 변형 여부도 명시한다. 이 스키마는 현재 등록 화면의 기본 프로필이며 원본의 모든 운영 옵션을 지원한다고 뜻하지 않는다.

**Point는 등록·편집·복사·보관할 수 있지만 현재 모의 실행은 지원하지 않는다.** 과거 USDT 기준가격, 원본 신호 브리지, OKX 선물 원장·체결·헤지 연결이 더 필요하다. UI에 ‘등록됨 · 실행 연결 필요’를 표시하고 실행 버튼과 서버 양쪽에서 차단한다. 계좌를 만들거나 단일 메이커로 대신 실행하지 않는다. 등록 상태를 사용자 임의의 `executable=true`로 변경할 수 없다.

### minmaxma · point_st

사용자 지정 이름은 **minmaxma 전략**이다. `minmaxma` 유형과 `builtin_minmaxma` 기본 프로필을 Point와 별도로 둔다. 기준가격 저점·고점·시간가중 MA 신호의 buffer 배수, MA 시간, 시세 지연, 보유·주문 한도를 등록한다. Binance 시세를 원본 참조로 하고 OKX 선택은 명시적 변형으로 기록한다. 기준 거래소에는 주문하지 않는다. 현재 등록·편집·복사·보관을 지원하며 재생 실행은 아직 연결 전이다. 소스·공식·설정·이론가 상태는 [minmaxma 상세 문서](../../docs/minmaxma_strategy.ko.md)에 있다.

## 버전과 저장

`.state/strategies.sqlite3`의 `strategies`는 ID·최신 버전·보관 상태를 갖는다. `strategy_revisions`는 `(strategy_id, revision)`을 고유 키로 이름·설명·유형·검증된 설정·프로필 근거·등록 시각을 JSON으로 보관한다.

- 최초 등록은 v1이다. 수정은 이전 값을 덮지 않고 v2, v3을 추가한다.
- 수정 요청의 `expected_revision`과 현재 최신 버전이 다르면 거절한다.
- 기존 전략의 유형은 바꾸지 않는다. 다른 유형은 새 전략으로 등록한다.
- 복사는 새 ID로 등록할 폼을 준비한다. 저장 버튼을 눌러야 실제 등록한다.
- 보관은 되돌릴 수 있다. 보관한 전략으로 새 실행은 시작할 수 없고 과거 결과는 남는다.
- 없는 기본 전략만 최초 한 번 생성한다. 서버 재시작으로 사용자 편집이나 보관 상태를 초기화하지 않는다.

새 실행 요청은 `strategy_id`와 `strategy_revision`을 보내며, 서비스는 등록 상태·실행 지원을 확인한 뒤 전체 설정을 `config.strategy`와 `initial_config.strategy`에 고정한다. 실행 중 다른 화면에서 전략을 수정해도 기존 worker 설정과 과거 체결 보고는 바뀌지 않는다. 설정 복사 재실험도 원래 버전을 명시적으로 선택한다.

전략 선택 필드가 없는 기존 API 요청은 기본 메이커를 사용한다. 이전 실행 기록에 전략 메타데이터가 없으면 UI는 ‘단일 거래소 메이커 (이전 실행)’로 표시한다. 이전 실행의 초기조건 복사는 기본 v1을 조회하며 최신 편집 설정으로 조용히 대체하지 않는다.

## 전략 이론가 → 계좌 평가 계약

확정 요구사항: **이론가 기준 미실현손익은 전략에서 계산한 이론가를 입력받는다.** 현재 7일 평균이나 계좌에 입력한 고정 숫자를 임의로 대체하지 않는다.

전략의 `theoretical_quote(quote, now_ms=...)`는 `TheoryOutput` 또는 `None`을 반환한다. 현재 재생기에서는 단일 종목의 KRW 이론가이며 다음 정보를 전달한다.

| 값 | 의미 |
|---|---|
| `price` | 전략이 계산한 양수 Decimal 가격 |
| `observed_at_ms` | 계산에 사용한 시장 관측 기준 시각 |
| `valid_until_ms` | 전략이 허용하는 마지막 유효 시각 |
| `basis` | 계산 방식 식별자 |
| `formula` | 계산식/근거 설명 |

실행기는 `accept_theory(output)`으로 받으며 가격을 새로 산출하지 않는다. 미래·만료 시각은 채택하지 않고, `None`이면 현재 값을 지운다. 평가 시점에도 유효성을 다시 확인한다. 전략 ID·버전·엔진 버전은 실행에 묶인 설정에서 붙인다. 자동 주문을 일시 중지해도 새 호가가 들어오면 전략의 평가 신호는 계산할 수 있다.

`이론가 미실현손익 = 보유 코인 × (유효한 전략 이론가 − 평균 원가)`다. 시장 미실현손익과 별도이며 둘을 합산하지 않는다. 이론가가 없거나 만료되면 포지션 이론가 평가와 관련 손익은 null이다. 보유량이 0이면 미실현손익은 0이다.

각 체결 보고에 **당시 전략 이론가·근거 시각·계산식·전략 버전**을 보존한다. 다음 호가에서 전략 이론가가 달라져도 과거 체결의 손익은 다시 계산하지 않는다. 화면에 현재 전략 이론가를, 거래 내역에는 당시 이론가와 기준 시각을 표시하며 전체 결과 JSON에도 포함한다.

신규 등록 전략 실행의 계좌 고정 이론가 입력은 받지 않는다. 예전 실행에 저장된 고정 이론가 보고는 그대로 보존한다. 이전 고정 이론가 실행을 복사할 때는 새 전략 출력 방식으로 바뀐다는 안내를 보여 준다.

Point의 이론가 출력식은 미결정이며 아직 가격을 출력하지 않는다. `OKX microprice × USDT microprice`인지 기준 조정 후 중심가격인지 등을 정하면 Point 어댑터에서 출력해야 한다. 이 항목을 비롯한 잠정 결정은 [미결정 사항](../../docs/strategy_registration_queries.ko.md)에 남겼다.

## API

| 요청 | 결과 |
|---|---|
| `GET /api/strategies` | 기본 유형·필드 스키마와 모든 최신 등록 전략, 보관 상태 |
| `POST /api/strategies` | 새 전략 v1 생성 |
| `GET /api/strategies/<id>?revision=N` | 지정 버전 조회, 생략하면 최신 |
| `POST /api/strategies/<id>/revisions` | `expected_revision` 확인 후 새 버전 저장 |
| `POST /api/strategies/<id>/archive` | `{"archived":true/false}` 보관/복원 |

등록 입력 예시:

```json
{
  "name":"BTC 매수 메이커",
  "type":"single_exchange_maker",
  "description":"매수 방향만 유지하는 비교 실험",
  "parameters":{"direction":"buy","max_quote_age_ms":1000,"theory_mode":"midprice"}
}
```

소수는 십진 문자열, 정수 항목은 정수로 보낸다. 알 수 없는 설정·유형·임의 코드 필드는 거절한다. 모든 API는 기존 로그인, POST는 CSRF를 검증한다. 세션 계정 하나의 전략 라이브러리이며 다중 사용자 권한 공유 기능은 없다.
