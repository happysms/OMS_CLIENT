# 원천 시세 데이터

이 폴더는 저장된 호가를 읽고 거래소의 공개 시세를 받는 부분입니다.

Parquet 가격은 거래소 원래 호가 단위를 유지합니다. 빗썸 BTC의 `b*_p`·`a*_p`는 KRW 가격이며, 빗썸 원본 수집기의 `b*_q`·`a*_q`는 수량×가격을 정수로 변환한 KRW 호가 금액입니다. 과거 조회는 완료 시간대의 저장 파일을 읽고, 공개 WebSocket은 실시간 시세를 받습니다.

- `parquet.py`: `/data/{거래소}/ob/{종목}/...` 탐색, 저장 범위 확인, DuckDB 호가 조회와 단일 종목 내보내기. `read_buckets`의 `price_mode=mean`은 평균, `last`는 같은 원본 행의 마지막 매수·매도 호가와 `quote_time`을 선택합니다. 파일은 읽기만 합니다.
- `quotes.py`: 빗썸·업비트·OKX 공개 WebSocket 연결, 재연결과 최우선 매수·매도 호가 정규화.
- `validation.py`: 시세 식별자, 시간·정수 검증, 조회 한도와 공통 오류 타입.
- `export.py`: 실제 저장 호가를 JSON 스냅샷으로 내보내는 CLI. `python -m oms_client.market_data.export --help`로 실행 방법을 확인합니다.
- `csv_export.py`: 선택 종목·기간의 원본 전체 행 또는 간격별 평균 호가를 CSV로 변환합니다. 원본 컬럼·중복 행·원본 시각을 유지하며 차트 샘플링을 적용하지 않습니다. UTF-8 BOM, 최대 31일·원본 100만 행·파일 256MiB 한도를 적용하며 초과 시 실패합니다. 문자열의 스프레드시트 수식 실행을 막기 위해 필요한 값에는 작은따옴표를 붙입니다.
- `funding.py`: 저장된 펀딩비율 목록·시간 범위와 마지막/평균 스냅샷을 읽습니다. 원단위 비율과 `%` 값을 함께 반환하며 음수·0을 보존합니다. 원본의 `nextFundingTime`은 잔여 초로 해석하고 확정 지급액을 만들지 않습니다.
- `funding_archives.py`: 과거 `.parquet.gz`를 제한된 용량의 비공개 임시 파일로 해제합니다. 일반 파일은 복사하지 않고 성공·실패 시 임시 파일을 정리합니다. 압축 파일당 32MiB·전체 256MiB·요청당 1,000파일 한도를 적용합니다.
- `ticks.py`: `/data/{거래소}/tick/{종목}/...`의 원본 체결 틱과 gzip 보관분을 읽습니다. 기록 시각 `desktopTime`으로 기간을 선택하고 차트는 구간 마지막 체결가 또는 산술평균, 원본 내역은 최신순 페이지로 제공합니다. 차트 축소와 페이지 이동은 전체 기간의 체결 수·거래량·최신 가격 통계에 영향을 주지 않습니다. 체결 ID가 없으므로 같은 값의 체결을 임의로 제거하지 않습니다. 빗썸·업비트만 수집기에서 확인된 수량 단위와 부호 방향을 표시하고, 나머지는 원본 부호 수량과 방향 미확인을 유지합니다.

체결 조회 API는 `POST /api/data/ticks`입니다. `exchange`, `ticker`, KST 또는 시간대가 포함된 `start`·`end`, `interval`, `price_mode: "last" | "mean"`, `offset`, `row_limit`을 받습니다. 조회 결과에는 전체 통계, 최대 6,000개 차트 표본, 최대 1,000개 원본 내역과 다음 페이지 여부가 포함됩니다. `POST /api/data/ticks/csv`는 같은 조건으로 **페이지·차트 표본과 무관하게 모든 원본 컬럼과 행**을 내보냅니다. 유효하지 않은 가격·수량도 CSV에는 보존합니다. 조회는 최대 31일·250,000구간·원본 500만 행, CSV는 원본 100만 행·256MiB이며 한도를 넘으면 전체 요청을 실패시켜 부분 파일을 제공하지 않습니다. 동시 체결 조회·CSV 생성은 합계 2개이고 DuckDB 시간·메모리 제한과 임시 정렬 용량 제한을 적용합니다.

새 데이터 형식이나 거래소 시세 연결은 여기에 추가합니다. 가격 조합식과 통계는 `../analysis/`, 체결·잔고 계산은 `../backtesting/` 또는 `../paper_trading/`에서 담당합니다. 실제 주문 API는 연결하지 않습니다.
