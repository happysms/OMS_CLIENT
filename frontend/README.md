# 화면 코드의 역할

`app.js`가 한 번 실행되고, `shell/`이 로그인 세션과 종목 목록을 읽은 다음 각 기능을 연결합니다. 가격·펀딩비율 조회·수식 계산·백테스트·모의 주문 체결은 서버 API가 담당하고, 이 폴더는 입력·진행 상태·결과 표시를 담당합니다.

```text
frontend/
├── app.js                       # 브라우저 진입점
├── index.html                   # 6개 탭의 화면 구조와 접근성 속성
├── styles.css                   # 공통 레이아웃·색상·반응형 스타일
├── shell/                       # 앱 시작, 기능 연결, 탭 이동
│   ├── bootstrap.js             # 세션·카탈로그 로딩과 초기화 순서
│   ├── workspace.js             # 기능 등록과 카탈로그 갱신 전달
│   └── tabs.js                  # 탭 선택, 키보드 이동, 분석 탭 이탈 시 실시간 종료
├── features/                    # 기능별 화면 로직과 해당 화면의 상태
│   ├── analysis/controller.js   # 조합식, 과거·실시간 분석, 프리셋·기록·CSV
│   ├── data/controller.js       # 단일 소스 조회·표, 원본/집계 CSV 생성·다운로드
│   ├── funding/controller.js    # 펀딩비율 조회·관측 메타데이터·전체 결과 CSV
│   ├── files/controller.js      # 왼쪽 파일 탐색기·메타데이터·파일 구간 조회
│   ├── backtesting/controller.js# 백테스트 조건, 자산 곡선·성과·체결 표시
│   ├── paper_trading/controller.js # 모의 잔고·포지션·주문·계좌 초기화
│   └── oms/                    # 추후 OMS 운영 화면이 들어갈 위치
├── shared/                     # 여러 기능이 함께 쓰는 화면 도구
│   ├── api.js                  # 쿠키·CSRF·로그인 만료·API 오류 처리
│   ├── charts.js               # 공통 캔버스 차트, 확대·커서
│   ├── dom.js                  # 화면 요소, 숫자·KST 표시, 입력·표 도구
│   ├── source-controls.js      # 거래소·종목 선택과 과거 데이터 범위 입력
│   └── jobs.js                 # 서버 작업 상태 조회와 오래된 응답 배제
└── scripts/check.mjs           # 모든 JavaScript 파일 구문 검사
```

## 기능을 추가하거나 수정할 때

- 분석식을 입력하고 결과를 보여주는 흐름은 `features/analysis/`에서 수정합니다. 실제 계산 규칙은 Python 서버 쪽에 둡니다.
- 분석 조건·가격 방식을 바꾸거나 기록을 불러올 때 이전 가격과 차트·표를 비우며, 이전 요청 응답과 CSV 다운로드가 뒤늦게 표시되지 않도록 실행 번호를 확인합니다.
- 특정 탭의 상태는 해당 `controller.js` 안에서 관리합니다. 데이터 조회와 백테스트의 실행 번호도 각각 관리하여, 조건 변경 전 응답이 새 화면을 덮지 않게 합니다.
- 탭에 공통으로 필요한 API·표시·차트 도구만 `shared/`에 둡니다. `shared/`는 특정 기능의 컨트롤러를 가져오지 않습니다.
- 새 탭은 `index.html`에 화면 구조를 만들고, `features/<기능>/`에 컨트롤러를 구현한 뒤 `shell/workspace.js`에서 연결합니다. 탭 전환·키보드 처리는 `shell/tabs.js`가 담당합니다.
- 서버 카탈로그가 바뀌면 `oms:catalog` 이벤트로 다른 화면의 선택 목록과 저장 범위를 갱신합니다.
- 파일 탐색기는 `shell/workspace.js`에서 연결하며 폴더별로 목록을 요청합니다. 조회 가능한 파일의 기간은 데이터·펀딩 컨트롤러의 `openQuery()`로 전달하고, 공유 입력 도구가 진행 중인 저장 범위 응답을 무효화해 파일 기간이 뒤늦게 바뀌는 것을 막습니다.
- 데이터 탭은 입력 조건이 바뀌거나 새 조회를 시작하면 이전 가격·차트·표와 조회 결과 CSV를 비웁니다. 응답을 표시하거나 파일을 다운로드하기 전에도 종목·기간·간격을 다시 확인합니다. 저장 범위를 뒤늦게 받아 기간을 자동 변경한 경우에도 이전 조회를 무효화하며, 사용자가 직접 편집한 기간은 덮어쓰지 않습니다.
- 데이터 탭은 기본으로 각 구간의 마지막 원본 행에서 매수·매도 1호가를 함께 조회합니다. `호가 조회 방식`에서 평균을 선택하면 구간 내 호가를 평균 냅니다. 원본 매수·매도 가격을 정수로 강제 반올림하지 않고 소수 자릿수를 보존해 표시합니다. 중간가는 두 호가 합의 절반이므로 소수점이 생길 수 있습니다.
- 원본 호가 모드는 서버의 `quote_times`로 차트·표·가격 기준 시각을 표시합니다. 종목·통화·조회 간격·방식을 함께 표시하고 차트 축은 숫자 라벨 폭에 맞춰 여백을 정합니다. 분석 탭도 `호가 조회 방식`을 제공하며 새 조회의 기본은 마지막 원본 호가입니다. 구간 평균을 선택하면 수식·차트·소스 카드·CSV가 모두 같은 평균 방식을 사용합니다. 소스 카드에 조회 방식과 원본 또는 구간 기준 시각을 표시합니다. 기록과 조합을 복원하면 저장된 방식을 유지하고, 방식이 없는 과거 기록·조합은 당시의 평균으로 복원합니다. 구형 브라우저 마지막 설정에 방식이 없으면 새 조회 기본인 마지막 호가를 적용합니다.

## 펀딩비율과 분석 소스

펀딩비 탭은 `/api/catalog`의 `funding_exchanges`에서 거래소·종목을 선택하고, `data_type=funding`으로 저장 범위를 조회합니다. `/api/analyses`에 단일 펀딩 소스와 수식 `A`를 전달하므로 파일 읽기·집계·CSV 생성은 서버에서 처리합니다. `last`는 구간 마지막 원본 비율, `mean`은 구간 내 비율 평균입니다. 차트는 최대 6,000개 점을 표시하며 CSV는 전체 조회 결과를 다운로드합니다. 거래소·종목·기간·간격·방식을 바꾸면 이전 결과와 CSV를 무효화하고, 오래된 작업 응답과 다운로드 본문도 배제합니다.

분석 탭의 소스 A~D마다 `가격 · 중간가`와 `펀딩비율 · %`를 선택합니다. 펀딩 소스의 `values`는 원본 `funding_rate`에 100을 곱한 퍼센트 값이며 화면에서 다시 변환하지 않습니다. 음수와 0을 유효한 값으로 표시합니다. 가격 소스는 기존 중간가·매수/매도 1호가·스프레드를 유지하고, 펀딩 소스는 % 값·원본 비율·마지막 관측시각·관측 당시 정산 잔여초를 표시합니다. 가격·펀딩을 함께 쓴 수식과 펀딩 소스끼리의 차이도 계산할 수 있습니다. 소스의 `data_type`은 저장 조합과 기록 복원 시 보존하며, 타입이 없는 과거 조합은 가격으로 복원합니다. Hyperliquid의 `xyz:AAPL` 같은 종목은 카탈로그의 대소문자를 보존합니다.

수집된 펀딩비율 스냅샷은 실제 계좌 지급·수취 금액이나 확정 정산률이 아닙니다. %는 각 거래소·종목의 원천 펀딩주기 기준이며 8시간 또는 연율로 자동 환산하지 않습니다. 서로 다른 주기의 `A - B`는 같은 기간의 펀딩 수익 차이를 뜻하지 않습니다. 평균 모드의 `source_times`, `server_times`, `next_funding_in_seconds`는 구간의 마지막 스냅샷 메타데이터이므로 평균값의 발생시각 또는 현재 카운트다운으로 해석하지 않습니다. 정산 잔여초가 없는 원본은 `—`로 표시합니다.

펀딩 소스는 저장 데이터의 과거 분석에서 지원합니다. 수식이 참조한 펀딩 소스가 있으면 실시간 시작 전에 안내하며, 수식에 쓰지 않는 펀딩 소스는 가격 실시간 분석을 막지 않습니다. 관측이 없는 구간을 앞선 펀딩 값으로 채우지 않고 공통 관측 구간만 조합합니다.

## 데이터 CSV 내보내기

데이터 탭의 CSV 영역은 위쪽 종목·기간 입력을 공유하고 차트 조회 없이 `/api/data/exports`에 파일 생성을 요청합니다. 원본 모드는 모든 원본 컬럼·행을 시간순으로 보존하며, 집계 모드는 선택한 조회 간격의 평균 데이터를 내보냅니다. CSV 생성 방식은 차트의 원본 호가·평균 조회 선택과 별개입니다. 기존 차트의 `조회 결과 CSV`는 선택한 호가 조회 방식의 결과를 다운로드합니다.

생성 상태를 조회해 완료된 파일의 행·컬럼 수, 크기와 보관 기한을 표시합니다. 선택 조건을 바꾸면 이전 요청 응답을 화면에서 제외하고 다운로드를 비활성화합니다. 다운로드 파일명은 서버의 응답 헤더를 사용하며, 인증 만료와 보관 기한 초과 오류를 표시합니다. CSV 계산과 변환은 서버가 담당합니다.

현재 실행에는 번들러나 프런트엔드 서버가 필요하지 않습니다. Flask가 로그인된 사용자에게 JavaScript 모듈과 CSS를 제공합니다. 새 공개 파일을 추가하면 서버의 정적 파일 허용 목록도 함께 갱신해야 합니다. 문서와 검사 스크립트는 웹 공개 대상이 아닙니다.

검사: `npm --prefix frontend run check` (저장소 루트에서 실행).
