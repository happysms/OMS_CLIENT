# OMS Client

모의거래의 지정가 142개 사례와 주요 전략·알고리즘 설명 그림은 [그림으로 보는 문서 안내](docs/visual_guide.ko.md)에서 볼 수 있습니다.

가격·펀딩비율 확인, 분석, 백테스트, 모의투자를 한 곳에서 사용하는 웹 도구입니다. 서버가 로컬 Parquet를 DuckDB로 조회·계산하고 브라우저는 조건 입력과 결과 표시를 담당합니다. 앞으로 OMS의 계좌·주문·전략 제어를 같은 작업 공간에 연결할 수 있도록 기능 모듈과 탭을 나눴습니다.

최근 요청 기능의 검증 결과와 구현 전 항목은 [2026-10-27 검증 보고서](docs/verification/2026-10-27.ko.md)에 정리했습니다.

## 현재 기능

| 탭 | 기능 |
|---|---|
| 데이터 | 오더북·체결 틱·펀딩비율·과거 1분봉의 종목·기간별 차트·내역·CSV, 왼쪽 파일 클릭으로 종류·종목·기간 자동 조회 |
| 데이터 품질 | 거래소별 `desktopTime − serverTime` 차트, 과거 통계·현재 모니터, 음수·시각 누락·임계값 초과 확인 |
| 분석 | A~Z 가격·펀딩비율·분봉 소스 추가와 조합, 과거 분석·실시간 가격 분석, 이동평균·수익률·Z-score, 조합 저장·분석 이력 |
| 백테스트 | 단일 종목 이동평균 전략, 다음 구간 체결, 수수료·슬리피지, 자산 곡선·지표·거래 내역 |
| 전략 관리 | Point·minmaxma·단일 거래소 메이커 유형으로 전략 등록, 설정·버전·복사·보관, 모의계좌 적용 |
| 모의투자 | 과거 데이터/실시간 시세 선택, 가상계좌·전략·주문·호가·틱·체결 손익·저장 결과. 과거 지정가·MM·1~32배속, 실시간 가상 시장가 주문과 공개 시세 |
| OMS | 계좌·주문·전략 제어를 연결할 예정인 영역. 현재 상태 조회만 제공 |

**모의투자는 하나의 기능입니다.** 이전 시뮬레이션·모의투자·실시간 시세 화면을 `모의투자` 탭으로 통합했습니다. 기본은 과거 데이터이며 `사용할 시세`에서 실시간으로 전환합니다. 기존 가상계좌·결과와 매칭/회계 규칙은 보존합니다. 실제 거래소 주문 입력은 모의투자 화면에서 노출하지 않습니다.

**실제 매매는 별도 IP의 실행 서버에서 수행합니다.** 이 대시보드는 파라미터 조절·실시간 관찰·거래내역 조회를 맡으며, 로컬 API 키 등록과 거래소 개인 요청은 기본 비활성화했습니다. [원격 전략 실행 서버 소켓 연동 정의서](docs/remote_execution_socket.ko.md)에 Point·minmaxma·단일 거래소 메이커별 계약, 메시지 스키마·예제, 재접속·설정 적용·체결 원장 규칙과 구현 순서를 정리했습니다. 원격 소켓 자체는 아직 구현 전입니다.

모든 탭 위의 **서버 PC 저장 공간 · 자동 정리**에서 남은 디스크 용량을 보고 시세 파일 보관 기간을 설정할 수 있습니다. 기본 7일·자동 삭제 꺼짐이며, 삭제 대상 미리보기와 저장소 선택을 제공합니다. 계좌·매매 결과는 보존합니다. [삭제 기준과 사용 방법](docs/storage_retention.ko.md)을 참고하세요.

각 기능 폴더의 `README.md`에 담당 로직과 수정 위치를 적었습니다. 계산 규칙은 `oms_client/`의 해당 기능에, 요청·응답은 `api/routes/`에, 화면은 `frontend/features/`의 같은 기능에 추가합니다.

요청 흐름은 `frontend → api/routes → 기능 로직 → market_data 또는 storage`입니다. 시장 데이터 접근은 `market_data/`에 모아 분석·백테스트·모의투자가 공유합니다. 분석용 실시간 시세의 연결·파싱은 `market_data/quotes.py`, 수식 계산과 시계열 누적은 `analysis/live.py`가 담당합니다. 수동 현물 매매의 공개 피드는 `manual_trading/market.py`에 분리하여 분석용 OKX 선물 수량과 섞이지 않도록 합니다.

## 실행

Python 3.12 환경에서 검증했습니다. 기존 작업 공간에서는 `/home/minsung1/dev/.venv/bin/python`을 사용할 수 있습니다.

```bash
cd /home/minsung1/dev/OMS_CLIENT
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python server.py --init-password
.venv/bin/python server.py --host 0.0.0.0 --port 8765
```

브라우저에서 `http://127.0.0.1:8765` 또는 `http://SERVER_IP:8765`에 접속해 비밀번호로 로그인합니다. `0.0.0.0`은 수신 주소이며 다른 기기에서는 실제 서버 IP를 사용합니다. 비밀번호를 바꾸려면 `--init-password`를 다시 실행하고 서버를 재시작합니다.

인증 상태와 세션 키는 `.state/dashboard.sqlite3`에 보관하며 비밀번호는 해시로 저장합니다. 조합·이력·모의 계좌도 이 DB에 저장합니다. 원본 시장 데이터는 기본 `/data`에서 읽고 수정하지 않습니다.

## 왼쪽 데이터 파일 탐색기

왼쪽 **데이터 파일**에서 `거래소 → 데이터 종류 → 종목 → 날짜 → 파일` 순서로 저장 항목을 펼쳐 봅니다. 호가·1초 호가·체결 틱·펀딩비율·과거 1분봉·환율을 구분하며 `.parquet`와 `.parquet.gz`를 표시합니다. 날짜 폴더와 파일명은 저장소의 UTC 기준이고 상세 정보·조회 화면은 KST 시각을 함께 사용합니다.

폴더를 펼칠 때 해당 목록만 읽고, 종목 검색·더 보기·새로고침을 지원합니다. 파일을 선택하면 용량·수정 시각·행 수·컬럼과 타입을 보여 줍니다. 원본을 읽거나 전체 폴더를 재귀적으로 스캔하는 대신 Parquet 메타데이터를 읽습니다. 압축 파일은 읽기 용량 제한을 적용하며, 메타데이터를 읽지 못하면 파일 크기와 수정 시각을 표시합니다.

호가·체결 틱·펀딩·분봉 파일을 클릭하면 데이터 탭으로 이동하고 데이터 종류·거래소·종목·파일 기간을 자동 적용해 조회합니다. 상세 영역의 **이 파일 구간 다시 조회**로 재조회할 수도 있습니다. 빠른 연속 선택에서는 이전 요청을 무효화하며 환율이나 현재 조회가 지원되지 않는 파일은 상세 정보를 표시합니다. 과거 1분봉은 완성 시각 기준으로 구간을 적용하며, 같은 종목의 우선 소스에 가려지는 기존 파일은 다른 데이터를 대신 열지 않습니다. 현재 수집 중인 틱은 Redis에 있고 완료된 시간별 파일이 만들어진 뒤 탐색기에 나타납니다. USDT 1초 수집 파일은 약 5초마다 갱신됩니다.

탐색기는 로그인이 필요하며 선언된 시장 데이터 경로만 읽습니다. API는 `GET /api/data/files`와 `GET /api/data/files/info`이고, 서버가 발급한 파일 식별자를 사용합니다.

## 체결 틱 조회

**데이터 종류 → 체결 틱**에서 저장된 거래소·종목을 선택하거나 왼쪽 체결 파일을 클릭합니다. 차트는 선택한 간격의 마지막 체결가 또는 산술평균이고 통계는 전체 유효 원본 체결을 사용합니다. 표는 집계하지 않은 체결의 기록 시각·거래소 시각·방향·가격·수량·원본 부호수량을 최근 순 100개씩 표시하며 페이지를 넘겨 이전 체결도 열람할 수 있습니다. 시각은 KST 밀리초까지 표시합니다.

`POST /api/data/ticks`는 최대 31일·500만 원본 행·25만 집계 구간을 조회하고 차트만 최대 6,000점으로 줄입니다. 빗썸·업비트는 수집기에서 확인한 부호로 방향을 표시하고 단위·부호 의미가 검증되지 않은 거래소는 미확인으로 표시합니다. 원본에 체결 ID가 없어 같은 값의 체결도 삭제하지 않습니다. 체결 없는 구간은 채우지 않습니다.

**원본 체결 CSV**는 표 페이지와 무관하게 선택 기간의 모든 원본 컬럼·행을 보존합니다. `POST /api/data/ticks/csv`는 최대 100만 행·256MiB이며 한도를 넘으면 기간을 줄여야 합니다. 차트에서 제외한 무효 가격·수량도 원본 CSV에는 보존합니다. 일반·압축 시간 파일을 지원하고 같은 시간에 둘 다 있으면 일반 Parquet를 우선합니다. 틱 조회·CSV는 동시에 2개까지 실행합니다.

## 거래소별 기록 시각 차이

**데이터 품질** 탭에서 거래소·데이터 종류·종목을 골라 `desktopTime − serverTime`을 밀리초로 비교합니다. 종목을 비우면 거래소별 BTC를 우선 사용하고, BTC가 없으면 해당 거래소의 첫 종목을 시리즈 제목에 표시합니다. 호가·체결 틱·펀딩·USDT 1초 호가를 지원하며 과거 조회는 최대 7일·8개 거래소입니다. 각 구간의 평균·P95·최댓값·최솟값 차트와 전체 원본 기준 P50/P95·음수·임계 초과·무효 시각 수를 제공합니다. 음수는 그대로 남기며 빈 구간을 이전 값이나 0으로 채우지 않습니다.

**현재 모니터**는 상위 수집기의 최신 Redis 기록을 2초마다 읽습니다. 같은 원본 기록 시각은 중복 추가하지 않고, 최대 900개·30분 범위를 유지하며 마지막 자료의 경과 시간을 별도로 표시합니다. 탭 이동·화면 숨김·설정 변경 시 중지합니다. USDT 1초 자료는 약 5초마다 갱신되는 최근 Parquet를 읽고, 채택 시각 기준 차이와 `receivedTime − serverTime` 수신 기준 차이를 함께 표시합니다. 이 수집기는 10초보다 오래된 호가를 저장하지 않으므로 누락도 함께 확인해야 합니다.

`desktopTime`은 브라우저 PC가 아닌 상위 수집 PC의 시각입니다. 차이에는 장비 간 시계 오차와 수집·전송·처리 시간이 포함되며 네트워크 왕복시간(RTT)이 아닙니다. 거래소 시각이 수집기에서 생성되는 OKX·Hyperliquid 펀딩, 날짜 없는 시분초 또는 생성 시각을 쓰는 LS 호가·틱은 측정 불가 사유를 표시합니다. 1분봉 보완 자료는 이 측정에 사용하지 않습니다.

현재 캐시는 서버 환경변수 `DASHBOARD_REDIS_URL`(기본 `redis://127.0.0.1:6379/0`)로 지정합니다. 인증 정보는 서버 설정에만 두며 URL 쿼리·프래그먼트는 허용하지 않습니다. 이 기능은 기존 Redis·Parquet를 읽기만 하며 수집기나 원본을 변경하지 않습니다. API는 인증된 `GET /api/quality/catalog`, `POST /api/quality/history`, `POST /api/quality/live`입니다.

## 데이터와 분석

데이터 탭의 **데이터 종류 → 펀딩비율**에서 저장된 펀딩비 내역도 조회할 수 있습니다. 거래소·종목·기간을 선택하면 퍼센트 차트와 원본 비율·관측/서버 시각·관측 당시 정산 잔여초를 표시합니다. 구간 마지막 원본 또는 구간 평균을 선택하고 **조회 결과 CSV**로 전체 집계 결과를 다운로드합니다. 평균의 시각·잔여초는 해당 구간 마지막 관측의 값입니다. 별도 펀딩 탭은 데이터 탭에 통합했으며 기존 `#funding` 링크는 데이터의 펀딩 조회로 이동합니다. 이 자료는 원천 펀딩주기의 비율 스냅샷이며 계좌별 실제 지급·수취 금액은 아닙니다.

원본 경로는 `/data/{exchange}/ob/{ticker}/{YYYY}/{MM}/{DD}/{HH}.parquet`입니다. 거래소·종목·날짜별 필요한 파일을 선택하고 DuckDB에서 조회합니다. 중간가는 `(bid + ask) / 2`입니다. 데이터·분석 탭의 새 조회는 각 구간의 마지막 유효 호가를 기본으로 사용하며, **호가 조회 방식**에서 구간 평균도 선택할 수 있습니다. 백테스트와 평균 집계 CSV는 시간 간격별 유효 호가의 산술평균을 사용합니다. 누락 호가를 이전 가격으로 채우지 않습니다.

데이터 탭의 **구간 마지막 원본 호가**는 같은 원본 행의 매수·매도 1호가를 함께 선택하므로 원래 호가 단위를 유지합니다. 매수 324원·매도 325원이면 중간가는 324.5원이며, 중간가는 주문 가격과 구분합니다. **구간 평균**을 선택하면 여러 틱의 평균을 계산하므로 매수·매도 평균에도 소수점이 생길 수 있습니다. 화면에 선택 방식·거래소·종목·통화와 KST 기준 시각을 함께 표시합니다.

기존 `/data` 수집기는 직전 완료 1시간을 Parquet로 저장하므로 조회 가능한 마지막 시각과 실시간 시세에는 차이가 있습니다. 아래의 USDT 전용 수집기는 현재 시간의 파일도 기본 약 5초마다 갱신합니다. 종목·기간·조회 간격·가격 방식을 바꾸면 이전 결과를 비우고 새 조회가 완료된 뒤 가격·차트·표를 표시합니다.

분석 탭도 선택한 가격 방식으로 소스 중간가·수식·차트·매수/매도 호가·CSV를 함께 계산합니다. 분석 기록과 저장한 조합을 복원하면 당시 가격 방식을 유지하며, 방식이 기록되지 않은 기존 결과는 당시 계산 방식인 평균으로 복원합니다. 구간 평균 가격은 원본 주문 호가보다 작은 소수점이 나올 수 있으므로 화면에 평균임을 표시합니다.

수식에는 사칙연산과 `MA`, `EMA`, `DIFF`, `RET`, `ZSCORE`, `ABS`를 사용할 수 있습니다.

```text
((A / B) / (C / D) - 1) * 100
MA(A / B, 60)
RET(A, 1)
ZSCORE(A / B, 60)
```

함수 기간은 유효한 공통 표본 수입니다. 누락이 있으면 60개 표본이 정확히 60분을 의미하지 않습니다. 준비 표본이 부족한 값은 비워 둡니다. EMA는 pandas의 `adjust=True` 방식이며 표준편차는 표본 표준편차입니다. 표시 단위는 계산을 자동 변환하지 않습니다.

한 번에 최대 31일·소스당 250,000구간을 요청할 수 있습니다. 이 값은 조회 요청의 상한입니다. 현재 로더는 `.parquet`를 읽으며, 기존 수집기의 `.parquet.gz`로 보관한 오래된 자료나 체결 `tick` 파일은 이 초기 버전의 조회 대상에 포함하지 않습니다. 실제 조회 가능 범위는 종목별 저장 시각을 확인해야 합니다.

실시간 분석은 서버가 거래소 공개 WebSocket에 직접 연결합니다. 빗썸·업비트 KRW 호가와 OKX USDT 무기한 호가를 지원하며 소스/수신 시각이 10초 이상 오래된 호가는 계산에서 제외합니다. 기존 Redis·Parquet 수집기와 별도 경로이므로 실시간 차트가 움직인다는 사실만으로 아카이브 수집 상태를 판단할 수는 없습니다.

## 분석 소스 추가

분석 탭의 **데이터 소스 → + 데이터 추가**로 E·F 등의 소스를 더합니다. 각 소스에서 거래소·종목과 가격·펀딩비율·1분봉을 선택하고 `E / F`, `MA(E - F, 60)`처럼 수식에 사용할 수 있습니다. 최대 26개(A~Z)까지 구성하며 저장한 조합·분석 이력·브라우저의 마지막 조건을 복원할 때 소스 목록도 복원합니다.

카드의 삭제 버튼으로 소스를 제거합니다. 수식에서 사용하는 소스는 먼저 수식에서 빼야 하며, 남은 소스의 이름은 바꾸지 않습니다. 삭제한 이름은 다음 추가 때 다시 사용할 수 있습니다. 실제 파일을 읽고 실시간 구독하는 대상은 수식이 참조한 소스입니다.

과거 조회의 `참조한 소스 수 × 요청 시간 구간 수`는 최대 1,000,000입니다. 기존 소스당 250,000구간·최대 31일 제한도 적용합니다. 소스가 많아 한도를 초과하면 기간을 줄이거나 집계 간격을 늘립니다.

## 분석 가격 기준과 유동성호가

분석의 각 가격 소스마다 **수식에 사용할 가격**을 선택합니다. 이 설정은 과거 분석과 실시간 분석의 수식·차트·표·CSV, 저장 조합과 이력에 함께 적용됩니다. 기존 조합은 매수·매도 1호가의 중간가를 유지합니다.

| 가격 기준 | 분석에 사용하는 값 |
|---|---|
| 중간가 | `(매수 1호가 + 매도 1호가) / 2` |
| 매수 N호가 | 매수 쪽의 1~5번째 호가 가격 |
| 매도 N호가 | 매도 쪽의 1~5번째 호가 가격 |
| 매수 유동성호가 | 지정 금액만큼 매도 호가를 낮은 가격부터 소진하는 평균 체결가 |
| 매도 유동성호가 | 지정 금액만큼 매수 호가를 높은 가격부터 소진하는 평균 체결가 |

유동성 금액은 해당 시장의 KRW 또는 USDT입니다. 매수는 그 금액을 지출하는 기준, 매도는 그 금액을 수취하는 기준입니다. 평균 체결가는 `목표 금액 / 체결 코인 수량`으로 계산하고 마지막 단계는 필요한 만큼만 체결합니다. 예를 들어 매도 호가가 100원에 2개, 110원에 3개일 때 300원 매수의 수량은 `2 + 100/110`개이고 평균가는 103.125원입니다.

저장된 최대 5호가의 정상적인 연속 구간만 사용합니다. 금액이 부족하거나 중간 호가가 누락되면 선택 가격은 빈 값입니다. 부분 체결 수량·깊이 진단값은 남을 수 있지만 이를 전액 체결 가격으로 표시하지 않습니다. 마지막 원본 방식에서는 마지막 스냅샷이 미충족일 때 앞선 체결 가능 가격으로 되돌아가지 않습니다. 평균 방식은 각 스냅샷의 선택 가격을 먼저 계산한 뒤 유효한 가격만 평균하며, CSV에 유효·누락 스냅샷 수를 기록합니다.

평균 CSV의 유동성 금액·체결 수량·사용 단계 진단값은 미충족 행의 부분 체결도 포함한 진단값 평균입니다. 선택 가격을 계산한 완전 체결 표본의 수량과 구분합니다. 상단 최근 유효 조합 값은 해당 유효값의 시각을 함께 표시합니다.

기존 빗썸·업비트·Binance·OKX 파일의 `*_q`는 개별 레벨의 정수 절삭 호가 금액입니다. 이를 각각의 가격으로 나눠 수량을 환산하므로 과거 유동성호가는 근사값입니다. 새 USDT 파일은 실제 코인 잔량을 사용합니다. 수량 단위를 확인하지 못한 거래소의 유동성호가는 계산하지 않습니다. 실시간 OKX는 공개 계약 정보의 `ctVal`과 통화를 검증해 계약 수량을 코인 수량으로 바꿉니다.

분봉과 펀딩에는 가격 기준 옵션을 적용하지 않습니다. 수수료나 표시 호가 밖의 시장 충격은 평균 체결가에 포함하지 않으며 실제 주문은 발생하지 않습니다. 소스 카드의 별도 매수·매도·스프레드와 `mid/bid/ask` API·CSV 컬럼은 최우선 1호가 기준을 유지하고, 선택 가격은 `values` 및 CSV의 `*_selected_price`에 보존합니다.

가격 leg의 API 옵션은 `price_basis: "mid" | "bid" | "ask" | "buy_vwap" | "sell_vwap"`, N호가의 `book_level: 1..5`, 유동성호가의 `liquidity_amount`입니다. 통화는 서버가 거래소에서 결정합니다. 예: `{"id":"A","exchange":"bithumb","ticker":"BTC","price_basis":"buy_vwap","liquidity_amount":1000000}`. 수식에 참조한 소스의 옵션만 검증·계산합니다.

## USDT 1초 호가 수집

`collect_usdt.py`는 빗썸·업비트 공개 WebSocket의 **KRW-USDT**를 구독하고, 1초마다 당시의 최신 매수·매도 1호가와 실제 USDT 수량을 함께 저장합니다. 가격은 KRW, `bid_size`·`ask_size`는 USDT입니다. 두 수량은 같은 원본 호가의 잔량이며 가격을 곱한 원화 금액으로 변환하지 않습니다.

현재 수집기는 같은 스냅샷의 2~5호가도 `b2_p..b5_p`, `a2_p..a5_p`, `bid_size_2..bid_size_5`, `ask_size_2..ask_size_5`에 저장합니다. 이전에 1호가만 저장한 구간은 추가 깊이를 빈 값으로 유지합니다. 기존 SQLite 미반영 행과 시간별 파일도 재시작 시 보존하며 깊이 컬럼만 선택적으로 확장합니다.

거래소 메시지는 일정한 1초 주기로 오지 않으므로 거래소 갱신 사이에는 같은 호가가 반복 저장될 수 있습니다. 거래소 시각이나 로컬 수신 시각이 10초보다 오래된 호가, 연결이 끊긴 상태, 유효하지 않은 가격·수량은 저장하지 않습니다. PC 정지나 처리 지연으로 건너뛴 초를 과거 값으로 소급해서 채우지 않습니다.

| 컬럼 | 의미 |
|---|---|
| `sampleTime` | UTC 1초 기준 시각(epoch 밀리초), 거래소별 중복 저장 방지 키 |
| `desktopTime`, `sampledAt` | 실제 호가 채택 시각(epoch 밀리초). 조회 기간과 마지막 원본 호가의 시각 기준 |
| `serverTime` | 거래소 호가 시각을 밀리초로 정규화한 값 |
| `receivedTime` | 해당 WebSocket 메시지를 로컬에서 받은 시각 |
| `b1_p`, `a1_p` | 매수·매도 1호가(KRW) |
| `bid_size`, `ask_size` | 같은 호가의 매수·매도 실제 수량(USDT), 소수 수량 유지 |
| `quote_age_ms` | 실제 채택 시각에서 거래소 호가 시각을 뺀 밀리초 |
| `price_unit`, `quantity_unit`, `sample_interval_ms`, `market` | `KRW`, `USDT`, `1000`, `KRW-USDT` |

수집 파일은 기본 `data/market/{bithumb|upbit}/ob_1s/USDT/YYYY/MM/DD/HH.parquet`에 UTC 시간별로 저장합니다. `DASHBOARD_COLLECTOR_DATA_ROOT`로 경로를 바꾸면 대시보드와 수집기에 같은 값을 적용합니다. 기존 `/data`는 읽기 전용으로 유지하고, 새 저장소는 기존 수집기의 `/data` 압축·삭제 작업과 분리합니다.

각 초의 표본은 먼저 SQLite WAL에 커밋하고 기본 약 5초마다 Parquet에 원자적으로 반영합니다. 따라서 대시보드 조회에는 정상 상태에서도 약 5초의 저장 반영 지연이 있습니다. 재시작하면 아직 반영하지 못한 표본을 복구하며, 상태와 임시 저장 DB는 기본 `.state/collectors/usdt/`에 둡니다. `DASHBOARD_STATE_DIR`를 지정하면 그 하위 `collectors/usdt/`를 사용합니다.

수집 서비스를 설치하고 상태를 확인하려면 다음을 실행합니다.

```bash
cd /home/minsung1/dev/OMS_CLIENT
OMS_PYTHON=/home/minsung1/dev/.venv/bin/python bash deploy/install_collector_service.sh
systemctl --user status oms-usdt-collector.service
/home/minsung1/dev/.venv/bin/python collect_usdt.py status
journalctl --user -u oms-usdt-collector.service -n 50 --no-pager
```

서비스 시작·중지·재시작은 `systemctl --user start|stop|restart oms-usdt-collector.service`를 사용합니다. 설치 없이 직접 수집하려면 같은 Python으로 `collect_usdt.py run`을 실행합니다. 별도 시험 저장소는 `--data-root /tmp/oms-usdt-smoke/data --state-dir /tmp/oms-usdt-smoke/state --duration 30`으로 지정할 수 있습니다. 상태 API는 로그인한 세션의 `GET /api/collectors/usdt`이며 거래소 연결, 마지막 표본·Parquet 반영 시각, 미반영 행 수와 오류를 확인할 수 있습니다.

Parquet 반영 후 데이터·분석 탭에서 빗썸 또는 업비트의 **USDT**를 선택합니다. 데이터 화면은 실제 USDT 매수·매도 수량을 추가로 표시하고, 마지막 원본 방식은 가격·수량을 같은 행에서 가져옵니다. 평균 방식은 같은 유효 원본 행들의 가격·수량 평균이며 표시 시각은 구간 시작입니다. 같은 종목의 기존 호가 저장소가 있으면 이 전용 1초 저장소를 우선합니다.

## 과거 USDT 1분봉 보완

수집 시작 전 USDT 가격은 거래소 공개 REST의 완료된 1분봉으로 별도 보관합니다. 데이터 탭에서 **1분봉 종가(과거 보완)**를 선택하고 빗썸·업비트 USDT를 조회합니다. 분석의 각 소스에서도 **1분봉 종가**를 선택할 수 있으며 수식의 값은 KRW 종가입니다. 거래량은 분봉의 체결 USDT 수량이며 주문장의 매수·매도 잔량과 구분합니다.

```bash
/home/minsung1/dev/.venv/bin/python backfill_usdt.py --days 30 --exchange all
```

기본 저장 경로는 `data/market/{bithumb|upbit}/candles_1m/USDT/YYYY/MM/DD.parquet`이며 UTC 날짜로 나눕니다. `--data-root` 또는 `DASHBOARD_COLLECTOR_DATA_ROOT`로 바꿀 수 있습니다. UTC 기준으로 같은 분봉을 중복 저장하지 않고, 기존 완료 분봉을 보존하며 날짜별 파일을 원자적으로 반영합니다. 완료된 페이지는 중단 후에도 남으므로 명령을 다시 실행할 수 있습니다. 공개 API 요청은 전체 초당 최대 3회로 제한하고 일시적인 오류에는 제한된 횟수로 재시도합니다. 빗썸은 KST 조회 문자열, 업비트는 UTC 문자열로 요청합니다.

`candleTime`은 분봉 시작, `availableTime`은 시작 1분 후의 완성 시각, `fetchedAt`은 실제 REST로 가져온 시각입니다. 역사 분석에서는 종가가 알려지는 이론적 시각인 **완성 시각**으로 조회 범위를 필터하고 집계 구간을 배정합니다. 결과 시각은 집계 구간 시작이며 5분·1시간 구간 전체값은 그 구간 종료 후 확정됩니다. 마지막 원본 완성시각도 따로 제공합니다. 진행 중인 분봉은 제외하고 체결이 없어 반환되지 않은 분은 빈 구간으로 유지합니다. 1분 이상 간격으로 조회할 수 있으며 1초 틱으로 늘려 채우지 않습니다.

마지막 방식은 구간 마지막 완료 분봉의 종가를, 평균 방식은 구간 내 완료 분봉 종가의 평균을 사용합니다. 두 방식 모두 OHLCV·거래대금·원본 분봉 시각은 구간 마지막 원본 분봉의 메타데이터입니다. 화면과 조회 결과 CSV에 이를 표시합니다. 분봉 CSV에는 가격 방식과 출처, 종가 값, 마지막 원본 OHLCV·거래대금·시작/완성 시각을 포함합니다. 실제 1초 매수·매도 호가와 잔량은 전용 호가 수집이 시작된 시점부터 제공됩니다.

## 펀딩비율 조회와 조합

**데이터 탭 → 펀딩비율**에서 거래소·종목·기간·간격을 선택하고 마지막 스냅샷 또는 구간 평균을 조회합니다. 저장된 펀딩비율의 차트·표·최소/최대와 관측 시각, 관측 당시의 정산 잔여 초를 확인하고 전체 결과를 CSV로 다운로드할 수 있습니다.

원천 경로는 `/data/{exchange}/funding/{ticker}/{YYYY}/{MM}/{DD}/{HH}.parquet`입니다. OKX·Binance·Hyperliquid의 실제 저장 종목을 표시하며, 과거 `.parquet.gz` 파일도 임시 해제해서 읽습니다. 같은 시간의 일반·압축 파일이 함께 있으면 일반 파일을 한 번만 읽고 원본은 수정하지 않습니다. 조회 기간은 최대 31일이며 종목별 실제 저장 범위를 확인할 수 있습니다.

`fundingRate`는 비율 원값이며, 화면과 분석 수식에는 **원값 × 100의 퍼센트 값**을 사용합니다. 예를 들어 `0.0001`은 `0.01%`, `-0.0001`은 `-0.01%`입니다. 음수와 0도 유효한 관측값입니다. 이 데이터는 거래소에서 수집한 펀딩비율 스냅샷이며 계좌의 실제 지급액·확정 정산 내역과 구분합니다.

분석의 각 소스를 **가격·중간가** 또는 **펀딩비율**로 선택할 수 있습니다. 예를 들어 A를 OKX BTC 펀딩비율, B를 Binance BTC 펀딩비율로 선택하고 `A - B`를 계산하면 퍼센트포인트 차이를 얻습니다. 결과 단위를 `%p`로 표시할 수 있습니다. 가격·펀딩비율의 혼합 수식도 지원하며 표시 단위 선택은 수치를 자동 환산하지 않습니다.

거래소·종목의 정산 주기를 자동으로 동일하게 맞추거나 연율화하지 않습니다. `next_funding_in_seconds`는 **해당 원본이 관측됐을 때 남아 있던 초**이며 현재 시각에서 새로 계산한 카운트다운이 아닙니다. 평균 조회에서도 원본·서버 시각과 정산 잔여 초는 그 구간의 마지막 관측 메타데이터를 표시합니다.

조합에는 공통 관측 구간만 사용하고, 없는 펀딩비율을 이전 값으로 채우지 않습니다. 현재 펀딩비율은 저장 데이터 조회와 과거 분석에서 지원하며, 참조한 펀딩 소스가 있는 수식의 실시간 가격 분석은 명확한 안내와 함께 제한합니다. 저장한 조합·분석 이력은 소스 유형과 가격 방식을 유지합니다.

펀딩이 포함된 CSV는 `%` 값, 비율 원단위(`*_funding_rate_ratio`), 원본·서버 KST 시각, 정산 잔여 초와 `price_mode`를 보존합니다. 구간 평균 파일에도 방식을 기록하며, 가격 소스의 중간가·bid/ask와 펀딩 소스의 비율 컬럼을 구분합니다.

## CSV 데이터 내보내기

데이터 탭에서 거래소·종목·시작·종료 시간을 선택하고 **데이터를 CSV로 내보내기 → 내보낼 데이터 선택 → CSV 생성 → 파일 다운로드** 순서로 사용합니다. 차트 조회를 먼저 실행하지 않아도 됩니다.

| 방식 | CSV 내용 |
|---|---|
| 원본 행 | 해당 기간의 모든 원본 컬럼. 호가 단계별 가격·수량, 중복 행과 비정상 호가도 보존하며 `desktopTime` 순으로 정렬 |
| 평균 집계 | 선택 간격의 `time_kst`, `exchange`, `ticker`, `currency`, `mid`, `bid`, `ask`, `spread`, `source_rows`. 유효 호가를 평균 내고 차트 샘플링 없이 모든 집계 구간 제공 |

기간 입력은 KST이며 시작은 포함하고 종료는 제외합니다. 원본 `desktopTime`·`serverTime`은 저장된 UTC epoch 밀리초를 유지하고, 집계의 `time_kst`는 `+09:00` 시간대가 있는 시각입니다. 파일은 UTF-8 BOM을 포함해 Excel에서 한글을 읽을 수 있습니다. 문자열이 스프레드시트 수식으로 해석될 수 있으면 앞에 작은따옴표를 붙입니다.

기존 빗썸·업비트 수집기의 `b*_q`·`a*_q`는 코인 수량에 가격을 곱해 정수로 저장한 호가 금액(KRW)입니다. 원본 CSV는 이 값을 그대로 유지합니다. 새 USDT 1초 수집분의 `bid_size`·`ask_size`는 실제 USDT 수량이며, 원본 CSV는 모든 시각·단위 컬럼도 보존합니다. 평균 집계 CSV에는 같은 구간의 평균 수량과 `quantity_unit`, `source_kind`, `sample_interval_ms`를 추가합니다. 조회 결과 CSV도 실제 수량이 있는 소스에 수량·단위 컬럼을 포함합니다.

한 번에 최대 31일, 원본 1,000,000행, 집계 250,000구간, 파일 256MiB까지 지원합니다. 한도를 넘으면 일부만 잘라 저장하지 않고 실패 이유를 표시합니다. 기간을 줄이거나 집계 간격을 늘려 다시 생성하면 됩니다. `.parquet` 호가 파일이 대상이며 압축 아카이브와 체결 `tick`은 포함하지 않습니다.

변환은 서버의 별도 작업 큐에서 실행합니다. 완료 파일은 `.state/data_exports/`에 비공개로 저장하며 다운로드에 로그인이 필요합니다. 파일은 완료 후 최대 1시간, 최대 8개·합계 256MiB까지 보관합니다. 보관 한도나 서버 재시작으로 사라진 경우 다시 생성해야 합니다. 화면에 파일명·행 수·컬럼 수·용량·만료 시각을 표시합니다. 기존 차트의 **조회 결과 CSV**와 분석·백테스트 CSV도 사용할 수 있습니다.

**조회 결과 CSV**는 화면에서 선택한 가격 방식을 사용합니다. 마지막 원본 호가 방식에는 `price_mode=last`와 소스별 `A_quote_time_kst` 등의 원본 시각 컬럼을 추가합니다. `time_kst`는 조회 구간의 시작이고 원본 시각은 실제 선택한 호가 행의 시각입니다. 별도 CSV 생성 영역의 **평균 집계**는 화면 가격 방식과 관계없이 평균을 내보냅니다.

## 백테스트 모형

초기 전략은 단기/장기 이동평균 비교(`ma_cross`)이며 API에서는 매수 후 보유(`buy_hold`)도 제공합니다. 이전 완료 구간의 중간가로 신호를 결정하고 **다음 구간 평균 ask로 매수, 평균 bid로 매도**합니다. 주문 시각은 구간 종료 시각입니다. 시작·종료의 미완료 구간은 제외합니다.

현금 범위에서 전액 매수하며 수수료·불리한 방향의 슬리피지를 각 매매에 반영합니다. 기본값은 초기 자금 1,000,000, 수수료 5bp, 슬리피지 2bp이며 입력해서 바꿀 수 있습니다. 이는 거래소별 실제 요율을 자동 조회한 값이 아닙니다.

구간 평균 체결은 연구용 가정이며 실제 주문장 체결을 재현하지 않습니다. 호가 잔량 소진·시장 충격·최소 주문·수량 단위·공매도·레버리지·펀딩은 반영하지 않습니다. 파생상품 호가를 선택한 경우에도 전액 현금 매수 보유의 가격 참고 모형이며 실제 선물 손익이 아닙니다. 화면의 계산 가정을 함께 확인하세요.

지표와 거래 내역은 전체 완료 구간으로 계산하고 차트만 최대 6,000포인트로 줄입니다. 체결은 작업당 최대 20,000회입니다. 체결 CSV는 차트 축소 전의 전체 거래 내역을 제공합니다.

## 모의투자 모형

현재 모의 계좌는 **KRW 현금·매수 보유**를 지원합니다. 빗썸·업비트 종목을 대상으로 매수는 최신 ask, 매도는 최신 bid에 계좌의 슬리피지·수수료를 적용합니다. 주문 가격을 브라우저에서 지정할 수 없으며 서버가 실시간 호가를 확인합니다.

오래되거나 뒤집힌 호가, 현금 부족, 보유 수량 초과 매도는 거부합니다. 매수 수수료는 평균 매입 원가에 포함합니다. 평가에는 bid를 사용하며 신선한 시세를 받지 못한 보유분은 평가액을 추정하지 않습니다. 잔고와 포지션·체결을 하나의 SQLite 트랜잭션으로 갱신합니다. 선택적 `client_order_id`를 사용하면 같은 요청의 중복 체결을 막을 수 있습니다.

최대 12개 포지션, 시세 구독 최대 32개를 지원합니다. 종목별 시세 구독을 격리하므로 한 종목의 구독 오류가 다른 종목의 시세를 지우지 않습니다. 초기화는 모의 장부만 비우고 설정한 초기 현금으로 되돌립니다. 모의투자 데이터는 서버 재시작 후에도 유지합니다.

## API와 기능 확장

로그인을 제외한 기능 API는 인증이 필요하며 변경 요청은 세션의 CSRF 토큰을 `X-CSRF-Token`으로 전달합니다.

| 영역 | 주요 경로 |
|---|---|
| 메뉴·버전 | `GET /api/modules`, `GET /api/version` |
| 데이터·분석 | `GET /api/catalog`, `GET /api/bounds`, `POST /api/analyses`, 결과·CSV 조회 |
| 데이터 파일 탐색 | `GET /api/data/files`, `GET /api/data/files/info` — 폴더 목록·파일 메타데이터 |
| USDT 수집 상태 | `GET /api/collectors/usdt` |
| 펀딩비율 | 카탈로그의 `funding_exchanges`, `GET /api/bounds?data_type=funding&exchange=okx&ticker=BTC`, 펀딩 소스를 지정한 분석 요청·CSV |
| 1분봉 종가 | 카탈로그의 `candle_exchanges`, `GET /api/bounds?data_type=candle&exchange=bithumb&ticker=USDT`, `data_type: "candle"` 분석 요청·CSV |
| 데이터 CSV 변환 | `POST /api/data/exports`, `GET /api/data/exports/{id}`, `GET /api/data/exports/{id}/csv` |
| 백테스트 | `POST /api/backtests`, `GET /api/backtests/{id}`, `GET /api/backtests/{id}/csv` |
| 모의투자 | `GET /api/paper`, `POST /api/paper/orders`, `POST /api/paper/reset` |
| OMS | `GET /api/oms/status` — 현재 연결 예정 상태 |

`POST /api/analyses`는 `price_mode: "last" | "mean"`을 지원하며 생략하면 기존과 같이 `mean`입니다. 마지막 원본 방식의 각 `legs`에는 실제 원본 시각(epoch 밀리초)의 `quote_times` 배열이 포함됩니다. 데이터·분석 탭은 새 조회에서 `last`를 기본으로 요청하고 선택한 방식을 명시해서 전송합니다. 가격 방식은 분석 이력·저장한 조합·조회 결과 CSV에도 유지됩니다.

USDT 전용 수집 소스의 price leg는 `bid_size`, `ask_size` 배열과 `quantity_unit: "USDT"`, `source_kind: "orderbook_1s"`, `sample_interval_ms: 1000`, `quote_time_basis: "sampled_at"`를 함께 반환합니다. 기존 호가 금액 컬럼을 실제 수량으로 해석하지 않습니다.

각 leg의 `data_type`은 `price`, `funding`, `candle`이며 생략하면 기존 가격 소스입니다. 펀딩 leg는 `values`(%), `funding_rate`(비율 원단위), `source_times`, `server_times`, `next_funding_in_seconds`를 반환합니다. 분봉 leg는 `values`(KRW 종가 또는 종가 평균), 마지막 원본 `open/high/low/close/volume/trade_value`, `candle_times`, `available_times`를 반환합니다. 두 유형 모두 가상의 bid/ask를 만들지 않습니다. 단독 조회도 `legs: [{id: "A", data_type: "funding", exchange: "okx", ticker: "BTC"}]`, `formula: "A"`, `unit: "%"`처럼 같은 분석 API를 사용합니다.

OMS 제어를 추가할 때는 계좌·실주문·전략 제어 어댑터를 `oms_client/oms/`에 두고 `api/routes/oms.py`와 `frontend/features/oms/`에 연결합니다. 모의 장부와 실계좌의 데이터·주문 경로를 구분하고, UI에 실제 연결 상태를 표시하는 구조를 유지합니다. 현재 백테스트 전략은 `backtesting/engine.py`가 담당하며 이후 공통 전략 실행기가 필요해지면 계산 부분을 추출해 공유할 수 있습니다.

## 배포와 외부 접속

현재 방식은 이 PC에서 Waitress와 Cloudflare Tunnel을 사용자 서비스로 실행하는 구성입니다. 원본 시장 데이터를 별도 호스팅으로 복사하지 않습니다.

```bash
cd /home/minsung1/dev/OMS_CLIENT
OMS_PYTHON=/home/minsung1/dev/.venv/bin/python bash deploy/install_user_services.sh --with-tunnel
systemctl --user status oms-client.service oms-client-route.service
/home/minsung1/dev/.venv/bin/python routing.py status
```

서비스 설치 전에 로그인 비밀번호와 `.tools/cloudflared` 실행 파일이 준비되어 있어야 합니다. `cloudflared`는 [Cloudflare 공식 배포](https://developers.cloudflare.com/tunnel/downloads/)에서 설치합니다. 실행 파일과 터널 자격증명은 Git에 넣지 않습니다.

Quick Tunnel 주소는 연결 프로세스를 새로 시작할 때 변경되며 가용성을 보장하는 고정 주소가 아닙니다. 최신 주소는 `routing.py status`로 확인합니다. [공식 안내](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)

사용자 로그인 시 서비스가 시작되도록 설정하며 로그아웃 이후까지 유지하는 시스템 설정은 별도로 변경하지 않습니다. 대시보드와 터널을 종료하려면 다음 명령을 사용합니다.

```bash
systemctl --user stop oms-client-route.service oms-client.service
```

주요 환경 변수는 `.env.example`에 있습니다. 이 파일은 예시이며 서버가 `.env`를 자동으로 읽지는 않습니다. 서비스 설치 스크립트는 `.state/service.env`에 실제 경로·허용 호스트·배포 커밋을 기록합니다. `OMS_TRUSTED_HOSTS`로 실제 접속 호스트 목록을 지정할 수 있습니다. HTTPS 전달 헤더는 로컬 프록시에서 온 값만 신뢰하며, 직접 외부 요청이 전달한 헤더는 신뢰하지 않습니다.

## 검증

코드 들여쓰기는 **공백 4칸**으로 통일합니다. 편집기에서는 `.editorconfig`를 적용하고, Python은 고정 버전 Black, JavaScript·HTML·CSS·JSON은 고정 버전 Prettier로 정리합니다. 셸 스크립트도 공백 4칸을 사용하며 변경 후 `bash -n`으로 구문을 확인합니다. 문자열·SQL·데이터 값의 공백은 코드 들여쓰기와 구분해 보존합니다.

```bash
python -m pip install -r requirements-dev.txt
npm --prefix frontend install
python tools/format_code.py
python tools/format_code.py --check
```

포맷 명령은 Git에서 관리하거나 새로 추가할 소스 파일만 대상으로 하며, 무시된 실행 데이터·가상환경·의존성 폴더를 순회하지 않습니다. 문서 본문과 생성된 SVG·Mermaid는 제외합니다.

```bash
cd /home/minsung1/dev/OMS_CLIENT
/home/minsung1/dev/.venv/bin/python -W ignore::DeprecationWarning -m unittest discover -s tests -p 'test_*.py'
npm --prefix frontend run check
```

인증·CSRF·경로 제한·조회 정렬·안전한 수식·작업 큐·원본 CSV 컬럼·행 보존·집계·파일 한도·비공개 다운로드·실시간 시세·USDT 1초 샘플링과 복구·실제 수량·백테스트의 다음 구간 체결·수수료·모의 장부 원자성·시세 유효성 등을 검증합니다. 원본 수집기나 운영 OMS를 재시작하거나 변경하는 테스트는 실행하지 않습니다.

## 과거 시뮬레이션

`시뮬레이션` 탭에서 종목·기간·초기 원화/코인을 입력합니다. 1×는 원본의 시간 간격을 그대로 재생하고 1~32× 배속, 빠른 일괄 실행, 일시정지·재개를 실행 중 전환할 수 있습니다. 시장 5호가와 틱 옆에 내 미체결 주문을 표시하며, 5호가 밖의 내 주문은 호가창 맨 위 별도 영역에 표시합니다. 각 체결의 손익을 저장하고 CSV로 내보냅니다.

초기 구현은 빗썸 현물 maker 모형이며 OKX는 선택적인 두 번째 참조 거래소입니다. 틱과 추정 대기열을 사용하므로 실거래 체결의 재현을 보장하지 않습니다. 자세한 계산·API·자료 한도·이론가 제약은 [재생 모듈 문서](oms_client/replay/README.md)에 있습니다.

전략 등록과 실행별 버전 고정, 전략이 제공하는 이론가 평가 계약은 [전략 모듈 문서](oms_client/strategies/README.md)에 정리했습니다. 임시로 적용한 선택과 나중에 답할 항목은 [미결정 사항](docs/strategy_registration_queries.ko.md)에 남겼습니다.
